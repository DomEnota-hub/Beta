## Требуемые дальнейшие решения

1. Назначить **ровно один** из шести финальных disposition каждому действительно отдельному информационному объекту из оставшихся Kotlin, генераторных, исторических и ZIP источников; связывать точный объект с canonical ID либо конкретным `SOURCE_GAP`. Наличие 254 reviews не решает этот пункт. Из 50 исторических документов информационный этап затрагивает 12 целиком (78 разделов), ещё 14 явных информационных разделов смешанных документов и десять действительно смешанных разделов, которые нужно разобрать по утверждениям. Остальные документы относятся к следующим этапам; их точные тексты сохранены.
2. Сохранить неопределённые исходные номера Ермака и восемь межвариантных ссылок ЧМЭ3 в закрытом состоянии до появления первичных данных. Не угадывать тождество по похожим заголовкам.
3. После информационной миграции выполнить диагностический этап: согласовать кандидаты с **уже существующим в Test** предупреждённым включением расширенного режима, проверить модель/вариант и provenance каждой карточки, отдельно решать разрешение действия. Исторические инструкции и личные заметки могут оставаться атрибутированной информацией в этом режиме без декларации нынешней нормы.
4. Отдельный функциональный этап: донорская числовая parity движка, legacy history reader/writer, сохранность пользовательских настроек и подписанное обновление. `HistoryStorageMigrationGate.legacyFormatVerified=false` сохраняется. Затем пользовательские маршруты, общие экраны, адаптивный UI и Android приёмка. Палитра относится к новой UI работе.

Ни один ограниченный кандидат этой ветки не подключён к runtime как опубликованная инструкция. На SHA `d26719c9a42caae7aee89683eb9a68b85c3d588c` [Modular architecture bootstrap 38688836565](https://github.com/DomEnota-hub/Beta/actions/runs/38688836565) завершился `completed/success`: проверки данных, JVM, Android lint, debug APK и индексируемые ресурсы в APK. Локально прошли 89 одиночных Python команд workflow и `git diff --check`. Последующий коммит только с этой записью требует отдельной фиксации CI на его SHA; `in_progress` не считается успехом. Draft PR не сливать на основании одного этого отчёта.
