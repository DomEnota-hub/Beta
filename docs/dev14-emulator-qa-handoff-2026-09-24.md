# Dev14 Android emulator QA handoff — 2026-09-24

## Точка остановки

Эмулятор Android API 34 в GitHub Actions успешно поднимается и доступен через `adb`.
Приложение собирается, устанавливается и запускается на виртуальном Pixel 6. Полный smoke-маршрут пока не завершён: работа остановлена после проверки прокрутки справки приёмки, чтобы не расходовать оставшийся лимит Work.

Актуальная версия приложения на момент проверки:

- `versionCode = 199`;
- `versionName = 1.2.2-dev14-beta50.3`.

Workflow переведён только на `workflow_dispatch`, поэтому новые push-коммиты не запускают дорогой эмулятор автоматически.

## Проверенная схема запуска

Файл workflow: `.github/workflows/dev14-emulator-smoke.yml`.

Подтверждённо работает следующая конфигурация:

1. `ubuntu-latest` и таймаут 45 минут.
2. JDK 17 через `actions/setup-java@v4`.
3. Android SDK Platform 34 и Build Tools 34.0.0 через `sdkmanager`.
4. Gradle 8.7 через `gradle/actions/setup-gradle@v4`.
5. Распаковка `RailBrakeCalculator.zip` в `buildsrc` и наложение `patch/`.
6. Сборка `:app:assembleDebug`.
7. Выдача `/dev/kvm` режима `0666` через правило udev.
8. `reactivecircus/android-emulator-runner@v2` со следующими параметрами:
   - API 34;
   - `x86_64`;
   - `google_apis`;
   - профиль `pixel_6`;
   - `-no-snapshot -no-window -gpu swiftshader_indirect -noaudio -no-boot-anim`;
   - отключённые системные анимации.
9. В поле `script` должна быть одна команда:

   ```bash
   bash "$GITHUB_WORKSPACE/qa/run_emulator_smoke_ci.sh"
   ```

   Runner выполняет отдельные строки `script` как отдельные shell-команды, поэтому многострочная конструкция с переносами здесь ломается.
10. Обёртка `qa/run_emulator_smoke_ci.sh` запускает `qa/dev14_android_smoke.py`, а затем всегда сохраняет сведения об устройстве и полный logcat.
11. Шаг `actions/upload-artifact@v4` с `if: always()` сохраняет `qa-evidence/`, даже если smoke завершился ошибкой.

## Как запускать без браузера

Прямой запуск через браузер и авторизация браузерной сессии не нужны.

Использовать уже проверенный временный trigger-workflow:

1. Fresh-fetch `dev14-integration` и зафиксировать source HEAD.
2. Создать временный workflow, запускающийся по push только собственного файла.
3. Выдать ему:

   ```yaml
   permissions:
     contents: read
     actions: write
   ```

4. Перед dispatch проверить:
   - `HEAD^` совпадает с ожидаемым source HEAD;
   - `HEAD` совпадает с `origin/dev14-integration`;
   - ожидаемые `versionCode` и `versionName` находятся в `app` и `patch/app`.
5. Выполнить:

   ```bash
   gh workflow run dev14-emulator-smoke.yml --ref dev14-integration
   ```

   с `GH_TOKEN: ${{ github.token }}`.
6. Дождаться именно `Dev14 emulator smoke`, скачать `dev14-emulator-smoke-evidence`, записать run ID, artifact ID и source SHA.
7. Удалить временный trigger-workflow и fresh-fetch итоговый HEAD.

## Исправленные проблемы инфраструктуры

1. Многострочное поле `script` распадалось на отдельные команды. Логика вынесена в `qa/run_emulator_smoke_ci.sh`.
2. Первый `uiautomator dump /dev/tty` на API 34 мог вернуть пустой ответ. Теперь UI-дерево сохраняется через `/sdcard/qa-window.xml` с повторными попытками.
3. На чистом эмуляторе `settings get system font_scale` возвращает `null`. Это значение теперь трактуется как `1.0`.
4. `cmd package resolve-activity --brief` на Android 14 печатает строку метаданных перед компонентом. Скрипт выбирает только строку формата `package/Activity`.
5. Кнопка `?` при шрифте 130% уходит за правый край горизонтальной панели приёмки. Smoke умеет прокрутить панель до неё, но сам факт скрытия зафиксирован как UX-дефект.
6. Одного вертикального свайпа недостаточно, чтобы дойти до последнего абзаца справки. Подготовлена проверка `scroll_up_until_visible`, выполняющая до четырёх свайпов до появления целевого текста.

## Важное ограничение

Эмуляторный workflow не изменяет содержимое или механизм доступа скрытого раздела. При полном аудите скрытый раздел проверяется только визуально и навигационно в пределах ранее согласованного объёма.
