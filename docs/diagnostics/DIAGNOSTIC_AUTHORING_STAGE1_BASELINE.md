## Пять категорий очереди для проверки источников

- **11:** есть кандидат с точным профилем; его содержание всё ещё требует проверки.
- **66:** кандидат покрывает только часть исполнений; перед написанием версии разделить область применимости.
- **8:** расширенный кандидат относится к другому исполнению; ветка для текущего исполнения остаётся не привязанной.
- **16:** в доноре явно не найден дополнительный метод; не заполнять его выдуманным текстом.
- **239:** отсутствует адресный источник расширенной ветки в закреплённом доноре; требуется исследование.

Для Ермака в исходном графе зафиксировано 675 ссылок на источники, но это ещё
не построчная проверка. Незакрытые пять номерных идентичностей, неоднозначность

   документа-кандидата имеют разные точные профили и источники.

## Контроль допуска к содержательной разработке (для каждого сценария)

1. Сопоставить canonical ID, исходный ID, точный файл/объект/хеш донора и граф.
2. Для **каждого технического утверждения и исполнимого действия** установить
   конкретное доказательство (документ, применимая редакция, пункт/страница/
   таблица, исполнение и условия), а не только общую библиографическую ссылку.
3. Независимо оценить safety/source/profile/оборудование. Неизвестность
   блокирует действие; историческая заметка никогда не повышает разрешение.
4. Подготовить и проверить **разные** графы `SHORT` и `DETAILED`:
   разветвления, `YES/NO/UNKNOWN`, STOP, ограничение выводов, доклад.
5. Для **каждой** из двух версий исследовать отдельную расширенную ветку,
   точно привязанную к сценарию и профилю. Отсутствие доказательства →
   `UNBOUND/SOURCE_GAP`, а не искусственный маршрут. Не копировать ветку
   между версиями как «две независимые».
6. Проверить достижимость и смысл ветвлений, отрицательные/опасные пути,
   вариантные gates, сохранение ссылок, историю и поведение на Android.
7. `CANDIDATE` не менять на `ACTIVE` по одному зелёному CI.
   Публикация — отдельная содержательная, нормативная и safety-приёмка.

Независимые оси: версия карточки; объём знаний; глубина отображения;
предупреждение расширенного режима; конкретный профиль; допускаемые действия.
Изменение глубины отображения не даёт право на архивные методы.
