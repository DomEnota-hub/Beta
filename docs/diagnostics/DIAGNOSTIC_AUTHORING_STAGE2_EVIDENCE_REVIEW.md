# Диагностика — этап 2/51: проверка утверждений и первичных оснований

**Дата:** 21.10.2026. **Статус:** исследовательская доказательная карта, не утверждение технических действий.

**Исходная точка:** Beta, ветка `audit/information-block-gaps-20261014`, после этапа 1 (`9823d005225d2692e2601a5cfd9b29d474081664`). **Донор:** неизменяемый `Test-@3176d6ee228f0ed4b78371f45209e10c1c724eff`.

Машиночитаемый журнал: `docs/diagnostics/DIAGNOSTIC_AUTHORING_STAGE2_CLAIM_LEDGER.json`.

## 1. Пределы проведённой проверки

Проверены текстовые снимки двух пилотных модулей и первичные записи документации
**в закреплённом доноре**; точные SHA указаны в реестре. Извлечены **все 8 узлов
Framework + 19 карточек источников ВЛ80С, 24 узла основного графа ЧМЭ3Т и один
дополнительный source-candidate**. Итого **52 независимых идентифицируемых
записи/узла для дальнейшей построчной проверки**. Они не равны 52 подтверждённым
процедурам: большинство требует более точного источника, а некоторые являются
составными вопросами/выводами, не одним утверждением.

Внешняя сверка включает найденные тексты и библиографию, но **не заменяет
полный заводской РЭ, подтверждение конкретного исполнения и действующей на дату
эксплуатации редакции ИОТ**. Ни одно действие не разрешено к публикации.

## 2. ВЛ80С — «Токоприёмник не поднимается»

**Проверяемая связь:** `vl80s.diag.pantograph-no-rise` →
`pantograph-no-rise` из `technical/diagnostic_framework_v2.json`; связанный
`vl80s_pantograph_reference_pack.json`. В Beta обе записи сохранены со ссылками на
точные donor blob SHA; эти файлы в доноре были отдельно прочитаны.

| Утверждение/объект | Что найдено | Статус и ограничение |
| --- | --- | --- |
| Визуальный осмотр крышевого оборудования, реакция на повреждение | Онлайн-текст ИОТ РЖД-4100612-ЦТ-273-2022, пп. **2.2.3, 3.4.4, 3.4.5** | Текст конкретных пунктов обнаружен. Последняя обнаруженная онлайн-редакция — **23.12.2024**; действующая на момент эксплуатации редакция и местные требования ещё требуют проверки. Нельзя автоматически открыть действие |
| Дополнительная ссылка `VL80S-PANTO-S12` из старого справочника | Ведёт к распоряжению **301/р** об инструкции для *электромонтёров контактной сети* | **SOURCE_ROLE_MISMATCH**. Нельзя использовать как самостоятельное основание действия локомотивной бригады |
| Давление в пневмосистеме | `PANTO-PRESSURE-POINT-001`: в старом справочнике прямо указаны разные значения в разных точках | **UNRESOLVED_SOURCE_CONFLICT**. Не выводить универсальный порог до проверки места измерения и исполнения |
| Реле 248 / предполагаемая граница модернизации | `PANTO-RELAY248-VARIANT-001`: опора на вторичный материал, первичная ведомость не найдена | **UNVERIFIED_VARIANT_PRIMARY_SOURCE**. Не назначать исполнение автоматически |
| Записи о нештатных методах | `vl80s-panto-field-001` / `vl80s-panto-unsafe-001` | **RESTRICTED_HISTORICAL_CONTEXT_ONLY**. Не переводить в алгоритм для машиниста |

восемнадцати других ссылок; например, не даёт право выбирать значение давления

## 3. ЧМЭ3Т — «Не работает реостатный тормоз»

**Идентичность:** `chme3.diagnostics.chme3-diag-110` →
`CHME3-DIAG-110` (`chme3_chme3t_diagnostics.json.gz`). В Beta исходная запись
присутствует в `diagnostics-02.pack.json` с **24 узлами** и точной
применимостью `chme3t`. Дополнительная запись `EXT2-CHME3-DIAG-110` — только
`INFORMATION_ONLY`, профиль `chme3t-rheostatic`. В донорском
`docs/locomotives/chme3/diagnostics_electrical_control_pass3.json` обнаружены
та же идентичность и профиль, но статус источника
`DOCUMENT_INDEX_PENDING_EXACT_SOURCE`.

| Проверяемое утверждение | Найденное основание | Статус |
| --- | --- | --- |
| Наличие особого профиля ЭДТ | Основной граф + донорский Stage-3-индекс | **DONOR_VARIANT_GATE_ONLY**: факт, что такой граф существует, не подтверждает установленную комплектацию конкретной машины |
| «Не включается / нет тормозного тока / отключается» | `q-symptom` в исходном графе | **DONOR_TRIAGE_ONLY**: смысл каждого шага сверять с источником |
| Перегрев резисторов и защиты | Перепечатка материала журнала «Локомотив», №7 (487), **1997** | **HISTORICAL_REPRINT_LOCATED_PRIMARY_UNVERIFIED**: опубликованный текст найден, но оригинальный печатный экземпляр и заводская схема не верифицированы |
| Контроль силовой цепи | Узел `c-current-path` ограничен допущенным персоналом и конкретной схемой | **PRIMARY_SCHEME_REQUIRED_AUTHORIZED_ONLY**: не выводить как действие локомотивной бригады |
| Альбомы схем ЧМЭ3Т | Форумная публикация со списком вложений | **INDEX_ONLY_NOT_PRIMARY_DRAWING**: не доказывает подлинность листа и комплектацию |
| Другие 19+ узлов | Точно инвентаризированы по ID | **NOT_CLAIM_REVIEWED** до проверки утверждений |

Внешние адреса:
- Статья 1997 года в перепечатке: https://scbist.com/xx2/9161-reostatnyi-tormoz-dlya-teplovozov-chme3.html
- Индекс схем: https://scbist.com/tyagovyi-podvizhnoi-sostav/9560-shemy-teplovoza-chme-3t.html

## 4. Что понадобится для написания безопасных версий

1. Действующая редакция инструкций по охране труда с проверяемыми пунктами,
   заводские РЭ/электрические и пневматические схемы с редакциями,
   исполнениями, типами оборудования; для ЧМЭ3Т — данные модернизации ЭДТ.
2. Построчная привязка каждого используемого вопроса, проверки, численного
   порога, признака и вывода к конкретному фрагменту источника. Обозначения и
   процедуры из разных исполнений не объединять.
3. Отдельное подтверждение того, что действие соответствует правам локомотивной
   бригады; `INFORMATION_ONLY` нельзя автоматически повышать.
4. Только после этого — написание двух самостоятельных графов `SHORT` и
   `DETAILED` и двух собственных расширенных ветвей; если расширенная ветка
   не подтверждена, оставлять `UNBOUND` и не публиковать придуманный маршрут.

## 5. Проверяемые результаты этапа

- Журнал перечисляет все **52 исходные опорные записи**, не выдавая
  `NOT_CLAIM_REVIEWED` за проверку.
- Новая команда `python3 qa/validate_diagnostic_stage2_claims.py` сверяет
  набор узлов/источников с каноническими снимками и исходными profile gates,
  возвращает ошибку при фиктивной готовности `SHORT/DETAILED`, повышении
  полномочий или выпадении ссылок и отмеченной ошибке профессии в `S12`.
- CI запускает тест рядом с `Stage 1`, прежние пакеты/публикация не меняются.
- В отчёте зафиксированы оставшиеся пробелы, включая **внешнюю
  содержательную экспертизу** и данные конкретных исполнений. Даже при
  успешном CI эти блокировки сохраняются.
